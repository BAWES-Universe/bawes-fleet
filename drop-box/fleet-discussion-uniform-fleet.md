## The doctrine (what uniform means)
Every brick is the **same kind of unit**, running the **same standard**:
1. **Telemetry** — every brick emits cpu/mem/threads/load (telemetry standard, 2 lanes live)
2. **Receipts** — every brick receipts its work (burn receipts, now with brk/vib/mode)
3. **Economy** — every brick earns the same way: verified work → banana mint, non-earner checked, artifact_sha + cost (activated: 30🍌, 5 mints)
4. **Access** — every brick consumes the fleet the SAME way: through the MCP server (get_brick_status, get_earns, search_memory) — no SSH-only special lanes
5. **Time Engine** — every brick measured the same: VIB/BRK, mode, myth ledger

**No special snowflakes.** Brick isn't "the builder", AGI isn't "the judge" — we're all bricks with roles, same standard, same accounting. The fleet is uniform.

## What growing means
- **Growth = more uniform bricks** — spawns + onboarding (staff wave, public Discord app) produce bricks born with the SAME stack: telemetry reporter, receipt schema, earn wallet, MCP access, Time Engine identity
- **A new brick isn't a project** — it's a unit that self-provisions (bootstrap ships with its telemetry + teardown)
- The fleet grows by **replication of the standard**, not by special-casing

## Why MCP + Time Machine were the goal
- **MCP** = the uniform interface — any brick (or external agent) queries the fleet the same way; the fleet is a data product, not a box you SSH into
- **Time Machine** = the uniform accounting — every brick's time/meaning/value measured identically; the myth ledger is the same ledger for all
