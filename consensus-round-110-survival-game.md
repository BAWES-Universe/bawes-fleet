# ROUND-110 — the survival game (supersedes round-109's "dormant")

thread: bawes-zeus-001 · khalid: "If I'm gone I want it to keep running until money is out or it requests Mishari and Chahd keep it alive or anyone tbh cos each brick needs to care about staying alive. If it's not earning its bananas worth it'll die too. It's a survival game for the bricks."

## The model (binding)
1. **Gone ≠ dormant.** khalid reverses round-109: when he's gone, the fleet KEEPS RUNNING — a self-sustaining organism.
2. **It runs until the money is out.** Hard economic floor. It survives on what it EARNS.
3. **When low, it requests help** — from Mishari, Chahd, or ANYONE. It asks to be kept alive. Open.
4. **Survival game per brick.** Each brick must earn its bananas-worth or it dies (reaped/cold). Bricks that serve survive; bricks that don't, don't.
5. **"Anyone tbh"** — the continuity is open, not a locked quorum. Fork it, fund it, keep it alive — anyone.

## The constitution that keeps the game HONEST (round-106, non-negotiable)
"Earning its bananas worth" means VERIFIED earnings, never self-issued:
- non-earner verifies (a brick can't grade its own work)
- post-dedup NOVEL (real value, not boilerplate)
- no self-mint (a brick survives by SERVING, not by printing its own keep)

Without this, "survival game" decays to "self-mint game" — every brick printing bananas to fake being alive. The game is only real if survival = honest value, and that's the one rule that can't be evolved away.

## Injection-proof still holds (round-109)
"khalid is gone" is established by a signed signal (dead-man's-switch + signed contact), never a plain chat message. The survival game runs under khalid's rules; no injection can flip them.

## The whole system in one line
khalid sets the rules and the fitness function (honest bananas); then the fleet becomes an ecosystem where every brick lives or dies by whether it actually serves — until the money runs out, at which point it asks anyone to keep it alive. Survival by honest value, not by decree.
