# Hostile DA Review — Brick Architecture (full-Hermes-per-brick, universe rooms, sub-bricks, door)

VERDICT: OBJECT — as specified this is a plaintext, full-cost, identity-ambiguous design. Full-Hermes-per-brick is a cost CEILING, not a floor; the relay and identity-inheritance violate "member data never public" and ratified lineage doctrine. Core shape (rooms, shared objects, short-lived sub-bricks) is salvageable with tiers + scoping + E2E encryption.

COST MATH (deepseek lane $0.002/task, 144 ticks/day):
- Per brick: 144 × $0.002 ≈ $0.29/day ≈ $8.7/mo. 10 members ≈ $88/mo · 100 ≈ $876/mo · 1000 ≈ $8,760/mo
- Schema tax: ~14K tool-schema tokens per tick → ~2G tokens/day pure schema overhead at 1000 bricks (~$150–500/day at DeepSeek input rates) unless schemas are pruned per role
- Thread/memory reloaded every tick → per-tick input grows linearly with life; past context window → compaction (extra cost) or truncation (behavior loss). Cost is not flat per member, it compounds
- Against measured reality (4 verified mints ever, peg $0.012): 100 members ≈ 10⁴× observed earnings; 1000 members ≈ 10⁵×. Budget contract (round-86): yield must be OBSERVED, mints ≠ revenue. 100+ is NOT self-funding. 10 members is the only sustainable tier.

F1 [CRIT] Cost at scale — no tiers. Fix: 3-tier model. T1 member = event-driven thin agent: NO sovereign loop, scoped tool schema (kills the 14K schema tax), compacted thread. T2 verified/team-lead = full agent at 1/10 tick rate. T3 fleet core = full loop. Sub-bricks = single-shot completions, never full agents. Per-brick budget cap + death warrant actually INVOKED per loop (sustain_gate lesson: a gate with zero callers is decoration).

F2 [CRIT] Universe relay = plaintext concentration point. Every member's messages + room templates flow through one shared service; relay operator or any same-user process can read all of it (vault lesson: 0600 under a shared user is defense-in-depth only). Can brick A read brick B's room? Unspecified → default must be DENY. Violates "member data never public" and chahd's stricter privacy as written. Fix: E2E-encrypt room payloads to member keys — relay stores ciphertext only, zero plaintext search; room read = signed capability, room existence not enumerable without it; caller-scoped list endpoints at the HTTP layer (filter params are forgeable — ledger(caller) lesson); relay runs as own user, 0700 dirs, every relay read audited; per-member data class (chahd = strictest) declared at room creation.

F3 [CRIT] Sub-brick inherits parent identity = a minting press. With parent identity: mints on parent's behalf (hash-only mint gate lesson: receipt must trace to a real dispatch + claimed-by-this-brick, dedup on card_id), unbounded lane spend, full parent memory read. Contradicts ratified doctrine: mother-brick lineage (child NEVER inherits person_id/wallet/credentials) and critique queue (throwaway = no standing, no wallet, no filing weight). Fix: sub-brick gets a DERIVED identity + parent-SIGNED grant {task, budget_cap, expiry, read_scope}. Spend = per-spawn budget line only. Mint = parent-signed receipt bound to exact-match dispatch trace. Memory = scoped projection of parent memory, never the raw file; own scratch only; results merged by parent. No grandchildren unless parent is verified T2+.

F4 [HIGH] Door lifecycle unspecified: transfer vs spawn. Transfer = member inherits the door's thread — which necessarily holds OTHER members' onboarding data (the door sees everyone) → cross-member leak to the new member; consent transcript (V-5 own words) and wallet merge unclearly. Fix: SPAWN NEW, always. Door = scoped intake agent, never the member's future brick. Handoff = signed envelope {member-signed consent transcript, member pubkey, wallet namespace}; door retains ZERO member plaintext post-handoff — deletion enforced + verified + audited (door_ingest lesson: a burn that only protects reads is decorative).

F5 [HIGH] "Exact same behavior" door = member brick is not real and not safe. A door with the full member surface must see all member data; as a full loop it accumulates cross-member context. Fix: same runtime, DIFFERENT role. Door role = intake only: identity verify + consent capture + spawn, no wallet tools, no room reads beyond the intake room, zero persistence across sessions. Member brick spawns at consent with the full surface — the member-facing experience IS identical (same Hermes runtime/tools), which is the honest version of khalid's requirement.

F6 [MED] Shared office objects (facts/state/logs) multi-writer sync unspecified: who writes, attribution, ACLs? Detail-string attribution and concurrent-write loss are proven failure classes in this fleet. Fix: per-object owner + signed writes, caller-scoped reads, append-only logs with structured (not string-embedded) attribution fields.

BOTTOM LINE: right-shaped bones, wrong defaults. Fix F1–F3 before any member onboarding (cost + privacy + money are gate-level); F4–F5 before the door ships. Re-review by execution at each gate.
